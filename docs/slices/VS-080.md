# VS-080 — Visibilidad por tema, corporativo evaluador y responsables corporativos

Estado: **implementado (2026-11-18), pendiente verificar en producción**. Extiende `docs/domain/business-units.md` (VS-050→059) y `docs/engines/permission.md`.

## Pedido (usuario)
1. Cada subindicador (tema) es una pregunta distinta → la **visibilidad por unidad se decide en el árbol**, sobre el propio tema: qué unidades lo ven.
2. El **admin corporativo también responde** parte de la evaluación → modo "evaluado" propio (no edita estructura, completa preguntas).
3. El corporativo puede **delegar** temas a un responsable de su área (ej. Talento y Desarrollo) que **no es admin corporativo**, igual que el admin de unidad delega hoy.
4. Unidades creadas (2026-11-18, por UI): FP Farmacias Peruanas, RP Real Plaza, SPSA Supermercados Peruanos.

## Diseño (mínimo, reutiliza lo existente)
- **Visibilidad**: no se crea tabla nueva. Sigue siendo `evaluation_assignment_exclusion` (`elementId = null` = tema completo). El árbol del Builder muestra por tema un selector "Visible para: [Corporativo] [FP] [RP] [SPSA]" que escribe/borra esas exclusiones (invertido: marcado = visible). El editor de exclusiones del panel Publicar (VS-059) queda como vista de detalle por elemento.
- **Corporativo como unidad más**: la matriz responde con `businessUnitOrganizationId = evaluation.organizationId` (ya es el valor por defecto de `response`, ver business-units.md). Se trata como una "asignación" implícita de la matriz: su visibilidad se guarda igual (fila de asignación propia para la matriz).
- **Modo evaluado del admin corporativo**: ruta `/mi-evaluacion` accesible a `corporate_admin` (hoy solo unit_admin/evaluator) mostrando los temas visibles para el corporativo; sin controles del Builder.
- **Responsables corporativos**: `evaluator` con `unitId = null` pertenece al corporativo; la tabla de bloques (`listBlocks`/`setBlockResponsible`, página `/responsables`) acepta la matriz como unidad y `corporate_admin` puede asignar. Ese usuario ve solo los temas que se le asignaron.

## Cambios previstos
- DB/servicio: asignación implícita de la matriz; `listBlocks`/`setBlockResponsible`/`assignResponsibleByEmail` aceptan `unitId = matriz`; `getAppContext` resuelve corporativo-evaluador.
- API: `/api/evaluations/[id]/blocks` permite `corporate_admin` con `unit` = matriz; endpoint de visibilidad por tema.
- UI: selector de visibilidad en el árbol (Builder), `/mi-evaluacion` para corporate_admin, `/responsables` con el corporativo.

## Decisiones (usuario, 2026-11-18)
- El corporativo **ve todos** los temas por defecto, pero la UI debe **distinguir con claridad cuáles le corresponde llenar** (los visibles para el corporativo) y cuáles son solo de las unidades (lectura, sin poder responder), para que no llene por error preguntas de las unidades.
- El responsable corporativo es un usuario del corporativo con rol `evaluator`, nada más.
- Esperado en el árbol/Runtime del corporativo: temas "Corporativo responde" (editables) vs "Solo unidades" (atenuados, solo lectura, etiqueta visible).
- Corrección MSA hecha (2026-11-18): 27 temas MSA rehechos; guía = banner, título y descripción = texto informativo.

## Criterios de cierre
Tests de servicio (visibilidad y aislamiento), typecheck, verificación en producción con las 3 unidades, docs/CHANGELOG/CHECKPOINT/BACKLOG.

## Implementación (2026-11-18)
- `appliesTo` (ya existente por elemento) ahora admite el id del corporativo; **ausente = todas las unidades, NO el corporativo**. El selector «Quién responde este tema» (cabecera del editor del tema) escribe `appliesTo` en todos los elementos del tema; el selector por elemento también muestra «Corporativo».
- `getAppContext`: miembro no-owner de la matriz = evaluador corporativo; `responderUnitId` (unidad propia o matriz). Rutas `for-business-unit/*` usan `responderUnitId` → el admin corporativo responde desde «Mi parte».
- El corporativo recibe el snapshot completo; lo que no es suyo viene con `viewerReadOnly` (solo lectura, etiqueta «Solo unidades de negocio · no editable»; lo suyo: «Responde el corporativo»). Escritura rechazada en servidor (`ANSWER_TO_UNIT_ONLY_ELEMENT`). El progreso del corporativo cuenta solo lo suyo.
- `/responsables` y `/users`: el admin corporativo asigna evaluadores del corporativo (unidad = matriz, «Corporativo»).
- Pendiente de verificar en producción; sin tests de DB automatizados nuevos (los de `packages/db` requieren Neon).
