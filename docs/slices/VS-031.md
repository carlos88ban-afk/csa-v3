# VS-031 — Builder: workspace split-view (árbol + editor)

Milestone: post-M12 (roadmap original cerrado en VS-015). Mejora de UX del builder: reemplaza la navegación por 5 páginas anidadas (Framework → Dimensión → Indicador → Subindicador → Editor) por un solo workspace de dos paneles con árbol de estructura lateral — patrón ya validado en el runtime público (`runtime-layout`/`runtime-nav`).

## Especificación previa

Diseño aprobado por discovery con la skill "impeccable" (shape: split-view de un solo workspace, ambos casos de uso — formularios pequeños con saltos entre niveles y formularios grandes, mismo patrón que el runtime):

- Nueva ruta `/frameworks/[frameworkId]/builder` — layout 2 columnas que hereda el patrón incumbente `runtime-layout`/`runtime-nav` (árbol izquierda 280px sticky, colapsable por dimensión/indicador, numeración automática VS-021, nodo activo destacado) + editor a la derecha con la lógica del editor actual (autosave, elementos, fórmulas, tablas).
- Las 3 rutas anidadas restantes (`dimensions/[dimensionId]`, `.../indicators/[indicatorId]`, `.../subindicators/[subindicatorId]`) **redirigen** al workspace con el nodo correspondiente seleccionado (`?s=<id>`); la página del framework conserva publicar/revocar + acceso "Editor".
- CRUD inline en el árbol (crear/renombrar/borrar con confirmación inline, sin diálogos nativos): crear indicador bajo dimensión, subindicador bajo indicador y subindicador directo bajo dimensión; crear dimensión desde el encabezado del árbol.
- Sincronización de selección por URL (`?s=<id>` vía `history.replaceState`, sin recarga); panel central con botones Anterior/Siguiente por la lista plana de subindicadores (mismo patrón que el runtime).
- Móvil (<860px): árbol como drawer deslizante con backdrop y botón "Estructura" en el panel del editor.
- Anti-metas: no tocar tokens visuales (`globals.css`) ni primitivas (`ui.tsx`), no tocar API/auth/runtime público, no rediseñar el editor elemento-a-elemento.

## Contratos

- `apps/web/components/subindicator-editor.tsx` (nuevo): editor de formulario de un subindicador **extraído literalmente** del page.tsx actual (autosave 1500ms, SaveStatus, elemento por tipo, opciones anidadas, tabla de datos, fórmula con `parseFormula`). Props: `{ subindicatorId: string }`. Sin Breadcrumb (la navegación la provee el workspace).
- `apps/web/app/frameworks/[frameworkId]/builder/page.tsx` (nuevo): workspace client component. Carga del árbol por lazy-load (no existe endpoint de árbol): `GET /api/frameworks/[id]` + `GET /api/dimensions?frameworkId=` en paralelo; por dimensión `GET /api/indicators?dimensionId=` + `GET /api/subindicators?dimensionId=`; por indicador `GET /api/subindicators?indicatorId=`. Mutaciones con los endpoints existentes (POST `/api/subindicators` con `indicatorId`|`dimensionId`, PATCH `/api/{dimensions|indicators|subindicators}/[id]`, DELETE).
- Redirects server (con `redirect()` de `next/navigation`, 307) en las 3 páginas anidadas → `/frameworks/[frameworkId]/builder?s=<id>`.
- `apps/web/app/frameworks/[frameworkId]/page.tsx`: links de dimensiones apuntan al builder (`?s=`); nueva sección "Editor" con acceso directo.
- `apps/web/app/globals.css`: clases `builder-layout`, `builder-nav*`, `builder-panel`, `builder-backdrop`, `builder-nav-toggle` + media query móvil (drawer).
- `apps/web/e2e/builder-publish.spec.ts`: reescrito al flujo workspace (crear dim → builder → crear ind/sub en el árbol → elemento → publicar).

## Fuera de alcance (explícito)

- Endpoint de árbol del lado del servidor (N+1 cliente es intencional; los contratos API quedan intactos).
- Drag & drop, reordenar dimensiones/indicadores, duplicar nodos, i18n.
- Cambios al runtime público (`/evaluations/[token]`), al flujo de publicación o a la autoridad visual del editor.
