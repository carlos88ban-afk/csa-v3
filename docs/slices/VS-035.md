# VS-035 — Borrado real, confirmaciones y solicitud de eliminación

Pedido del usuario el 2026-11-18. Pruebas en producción (datos de prueba).

## Principio
Borrar es **borrar**: las filas se eliminan de la base de datos (con sus dependientes por `ON DELETE CASCADE`) y los archivos de evidencia se eliminan del almacenamiento. No hay marcas «inactivo» para lo que el usuario borra. (La opción «Desactivar» de una unidad sigue existiendo como acción distinta; no es borrar.)

## Quién puede borrar
- **Administrador corporativo**: evaluaciones completas, dimensiones, indicadores, bloques, unidades y usuarios. Las rutas lo exigen en el servidor, no solo en la pantalla.
- **Administrador de unidad**: no borra. Puede **solicitar** la eliminación de un usuario de su unidad; el corporativo la confirma.
- **Evaluador**: nada.

## Confirmaciones (siempre con aviso «no es reversible»)
| Qué | Confirmación |
|---|---|
| Evaluación completa (Estructura) | Aviso + escribir `ELIMINAR`. El servidor también exige `confirm: "ELIMINAR"`. |
| Dimensión, indicador, bloque (Builder) | Aviso «no se puede deshacer» + «¿Seguro?» |
| Usuario (corporativo) | Aviso + «¿Seguro?» |
| Unidad (corporativo) | Aviso (borra también sus usuarios y respuestas) + «¿Seguro?» |
| Usuario (admin de unidad) | «¿Seguro que desea solicitar la eliminación de este usuario?» → crea una solicitud |

## Solicitud de eliminación de usuario
- Tabla `deletion_request` (`id`, `user_id` → user con cascade, `unit_id`, `requested_by`, `created_at`); una por usuario.
- `POST /api/users/:id/deletion-request` (admin de unidad, usuario de su unidad, no a sí mismo).
- `GET /api/deletion-requests` (corporativo): lista pendientes.
- `POST /api/deletion-requests/:id` con `{ approve: boolean }` (corporativo): aprobar borra al usuario (y con él la solicitud); rechazar borra la solicitud. Nada se queda guardado como «rechazada».
- El corporativo ve las solicitudes arriba en Usuarios, con «Aprobar y eliminar» / «Rechazar». El admin de unidad ve «Eliminación solicitada» en la fila.

## Archivos de evidencia
Al borrar una evaluación se eliminan del almacenamiento los objetos con prefijo `evaluations/{evaluationId}/` (mejor esfuerzo: si el almacenamiento falla, la base se borra igual y el error queda en el log).

## Unidades
`DELETE /api/units/:id` (corporativo): borra los usuarios cuya única unidad es esa y luego la organización (cascade: miembros, bloques asignados, respuestas, consultas, asignaciones).
