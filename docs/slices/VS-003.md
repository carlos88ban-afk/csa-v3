# VS-003 — Auth + Organización

Milestone: M1

## Especificación previa

`../domain/organization-user.md` (doc-first, escrito antes de este slice).

## Contratos

- `apps/web`: primera aplicación Next.js del monorepo (App Router), desplegable en Vercel Hobby (`../adr/0001-hosting-nextjs-vercel-hobby.md`).
- Better Auth con plugin `organization`, conectado a Neon vía Drizzle adapter (`../adr/0002-database-neon.md`).
- Email/password como único método de auth (sin proveedores OAuth externos en este slice — no decidido en `../architecture/stack.md`).
- Envío de email del plugin **desactivado**; invitaciones exponen el link de aceptación directamente (ver justificación en `../domain/organization-user.md`).
- Contratos de sesión/organización compartidos vía `packages/sdk-core` (SDK-first).

## Fuera de alcance (explícito)

- RBAC granular (dueño/editor/evaluador) — es M11 (VS-014). Aquí solo `owner`/`member`.
- Envío real de email — requiere una ADR de proveedor que no existe aún.
- OAuth social login — no solicitado, no se añade sin necesidad (evitar features especulativas).

## Decisiones tomadas durante la implementación (no 100% especificadas en el contrato original)

- Los tests corren contra el proyecto Neon real (no había Docker ni una BD de prueba separada disponible) — ver `../RISKS.md` R-005 para la mitigación (limpieza automática por test).
- `DATABASE_URL` provista es la conexión directa de Neon, no la *pooled* — ver `../RISKS.md` R-006, no bloqueante para este slice.
- Se añadió `dotenv-cli` como dependencia compartida para que `packages/db` y `apps/web` carguen el `.env` de la raíz de forma consistente en `build`/`test`/`dev`/`db:*`, incluyendo dentro de Turborepo.
- El esquema de Better Auth se generó con su CLI oficial (`@better-auth/cli generate`) en vez de escribirse a mano, para garantizar compatibilidad exacta con el runtime.
- Roles del plugin `organization` se dejaron en sus valores por defecto (`owner`/`member`/`admin` disponibles) pero el flujo de VS-003 solo ejercita `owner` y `member`, según lo especificado en `../domain/organization-user.md`.
