# VS-004 — Dominio core CRUD + schema (Framework→Dimensión→Indicador→Subindicador)

Milestone: M2. Fusiona el VS-004 (API) y VS-005 (migraciones) del roadmap original — ver `../domain/evaluation-hierarchy.md`, nota de alcance.

## Especificación previa

`../domain/evaluation-hierarchy.md` (doc-first).

## Contratos

- Schema Drizzle en `packages/db` para `framework`, `dimension`, `indicator`, `subindicator`, todas con `organizationId` denormalizado, aplicado a Neon con `drizzle-kit push`.
- Tipos/contratos compartidos (input/output de cada operación) en `packages/sdk-core` — SDK-first, consumidos tanto por la API como por el futuro Builder (M3).
- Funciones de servicio en `packages/db` con tenant-scoping y validación de jerarquía (el padre referenciado debe pertenecer a la misma organización que la sesión activa).
- Rutas API REST en `apps/web` (`/api/frameworks`, `/api/dimensions`, `/api/indicators`, `/api/subindicators`) que autentican vía Better Auth y delegan al servicio.

## Fuera de alcance (explícito)

- Elementos/form engine dentro de un Subindicador — M4 (VS-007). `formSchema` existe como columna pero se mantiene `null` en este slice.
- RBAC granular — M11. Cualquier `member`/`owner` de la organización puede operar.
- Paginación — se añade si el volumen real lo justifica, no especulativamente.
- UI del Builder — M3 (VS-006).

## Decisiones tomadas durante la implementación

- `formSchema`/`revisionNumber` sí existen a nivel de servicio (`updateSubindicator` en `packages/db`) para no rediseñar esta capa en M4, pero **no se exponen en la API pública** (`updateSubindicatorInput` de `sdk-core` solo acepta `title`/`description`) — consistente con `evaluation-hierarchy.md`.
- Autorización a nivel de servicio: las funciones `create*/get*/list*/update*/delete*` reciben `organizationId` ya resuelto (no `headers`) — la responsabilidad de autenticar y resolver la organización activa es de `requireActiveMember`, usada en las rutas API. Esto mantiene el servicio testeable sin HTTP de por medio.
- Bug real encontrado y corregido: los imports relativos con extensión `.js` desde `app/api/**/route.ts` hacia `apps/web/lib/` fallaban en el bundler Turbopack de Next.js 16 ("Module not found") aunque `tsc` los resolvía bien. Se cambió a los alias `@/*` ya definidos en `tsconfig.json` — más robusto y ya era la convención disponible.
- `firstOrThrow` añadido en `packages/db/src/domain/service.ts`: con `noUncheckedIndexedAccess`, el resultado de `.insert(...).returning()` se tipaba como posiblemente `undefined`; se hace explícito en vez de usar `!`.
