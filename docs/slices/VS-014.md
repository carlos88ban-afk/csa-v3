# VS-014 — Permisos (RBAC: dueño / editor / evaluador)

Milestone: M11. Refina el rol binario `owner`/`member` (M1/VS-003) en tres roles con permisos distintos, y expone por primera vez en la app la gestión de miembros/invitaciones.

## Especificación previa

`../engines/permission.md` (diseño completo: por qué sin `access-control` custom de Better Auth, matriz de permisos, por qué invitar/listar/gestionar miembros no necesita rutas API nuevas). No se repite aquí.

## Contratos

- `packages/db/src/authz.ts`: `requireWriteAccess(headers)` (nuevo), `AuthzError` gana el código `"FORBIDDEN"`.
- Rutas de escritura del dominio (`POST`/`PATCH`/`DELETE` en frameworks/dimensions/indicators/subindicators/evaluations) cambian `requireActiveMember` → `requireWriteAccess`. Rutas de lectura (`GET`, incluida `evaluations/[id]/export`) no cambian.
- UI: `apps/web/app/organizations/page.tsx` (sección de miembros/invitaciones, solo `owner`), `apps/web/app/accept-invitation/[invitationId]/page.tsx` (nueva).

## Fuera de alcance (explícito)

Ver `../engines/permission.md` (access-control granular por recurso, múltiples `owner`, envío de invitación por email, permisos sobre Evidencias/Respuestas del evaluado).
